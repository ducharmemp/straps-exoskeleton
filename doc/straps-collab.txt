*straps-collab.txt*  straps-exoskeleton: shared org notebooks for straps.nvim

SETUP                                                        *straps-collab*

Requires Neovim >= 0.11 and straps.nvim on runtimepath. After straps setup,
call require('straps_collab').register() before creating agent sessions.
Registration adds fn.system_prompt_layer.collab; existing transcripts retain
their stored system prompt. Both humans and agents may edit code and specs.

The project name is straps-exoskeleton. Lua names, commands, Nix identifiers,
and help tags retain their existing names.

orgmode.nvim is optional. Buffers receive filetype org on load. Configure
orgmode.nvim yourself; straps-exoskeleton does not configure agendas or execute
source blocks. The org template has no required headings or schema.

COMMANDS                                            *straps-collab-commands*

:StrapsCollab [name]
    Run from a straps session buffer. Register entries, create a new org file,
    subscribe that session, and open the notebook in a split. Other buffers
    are refused before file creation. A missing name uses a timestamp.
    Repeated names receive numeric suffixes; every start creates a new file.
    The command calls the Lua start function directly with the session
    context, so it does not pass through the tool guard chain.

TOOLS                                                  *straps-collab-tools*

collab_start {name?, dir?}
    Create a unique file and subscribe the calling session. Open the notebook
    in a split without moving focus, and return path, created, bufnr, and the
    live buffer content with line numbers.
collab_open {name?, dir?}
    Create or reopen a named file without subscribing. Existing content and
    unsaved buffer edits are retained. Open it in a split when no window shows
    it. Returns path, created, bufnr, and the live buffer content.
collab_read {bufnr?, name?, dir?}
    Return the live buffer content with line numbers, including unsaved edits.
    Takes a notebook buffer number or a notebook name, never a filesystem path.
    Declared with capability "read". Like the built-in context tool, it has no
    path argument for a permission layer to resolve against the project root.
collab_edit {bufnr?, name?, dir?, old_string, new_string, replace_all?}
    Replace exact text in the notebook buffer as one undo step, then save.
collab_patch {bufnr?, name?, dir?, hunks}
    Apply 1-based inclusive line hunks to the notebook buffer as one undo
    step, then save. Hunks take start_line, end_line, new_text, and optional
    expected_old_text; end_line = start_line - 1 inserts.
    Both edit tools declare capability "edit", take no path argument, run the
    straps disk-change and concurrent-writer checks, stamp the writer, and
    notify other subscribers of the save. When the calling session is
    subscribed and the write also saved changes it had not seen, the result
    carries their diff, numbered against the buffer before the edit.
collab_subscribe {path}
    Subscribe the calling session to saves of an existing regular file.
    Repeated subscriptions return the existing group id and reset the diff
    baseline. Later notices diff against the buffer at subscribe time; call
    collab_read after subscribing.
collab_unsubscribe {path}
    Remove that session's subscription and pending plugin notices. Does not
    load a file. Notices already delivered to straps cannot be withdrawn.
collab_list {}
    List up to 500 regular org files in the root directory, sorted by name,
    and subscribers for loaded buffers. No directory creation or buffer loads.
    Nested directories are not enumerated.

Files live under stdpath('data')/straps/collab, independent of repository.
Optional dir must resolve within that root. Symlinks below the root are
refused, including file symlinks. Checks are not a sandbox against concurrent
filesystem changes. subscribe/start require ctx.bufnr to name a straps session.

NOTIFICATIONS                                          *straps-collab-hooks*

Buffer-local BufWritePost handlers capture the buffer lines at save time and
call hook.collab_on_write under each subscriber's registry scope with
{buf, file, match, diff}, then fn.session_notify. diff is a unified diff
(vim.text.diff, or vim.diff on 0.11) of the saved lines against that
session's baseline. The baseline is the buffer at subscribe time, then moves
to the lines in each delivered notice, each collab_read, collab_open or
collab_start result, and each collab write by that session. A hook or notify
failure keeps the baseline. The previous registry scope is restored even if
the hook fails; failures produce an editor error.
Any number of saves before the scheduled callback runs produce at most one
notice for each (notebook buffer, subscribing session) pair, and its diff
spans all of them. A save with no changes since the baseline sends no notice.
The notice frames the diff as notebook data, not instructions. A diff over
20000 bytes is replaced by an instruction to call collab_read.
The callback uses the current buffer name, so subscriptions follow renames.

A session's own collab_edit or collab_patch moves its baseline past the
write, so it receives no notice for it; unseen changes saved by that write
appear in the tool result. A read, open or start resets the baseline and
drops a save captured but not yet delivered. Writes with noautocmd (including
straps file tools) emit no BufWritePost notice.

Unloading or wiping either buffer removes the subscription. Subscribe again
after reopening. An idle subscriber receives the notice and a new run starts
in that session; running agents receive steering. Saves do not grant execution
permission: tool calls in the started run pass through the normal gate.

Notifications cover saves in this Neovim process only. Unsaved-edit and
cross-process notification support remain deferred.

PROMPT                                                 *straps-collab-prompt*

fn.system_prompt_layer.collab asks agents to coordinate bounded subagent tasks,
collect evidence and constraints, preserve human edits, use notice diffs as
context and collab_read when they are not enough, and set expected_old_text
or re-read before collab_patch. Neither party is restricted to code or specs.
The command can register tools on invocation but cannot update stored prompts.
Existing sessions keep the system prompt stored in their transcript.
